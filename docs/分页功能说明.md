# 商品分页加载功能说明（手动实现版）

## 功能概述

实现了前后端分页读取商品数据的功能，每次从数据库读取 8 条数据，支持下滑加载更多。

**特点：不使用 MyBatis-Plus 分页插件，完全手动实现分页逻辑。**

## 后端实现

### 1. 创建分页结果类 `PageResult.java`

位置：`petserver/src/main/java/com/yellow/petshop/model/PageResult.java`

包含以下字段：
- `current`: 当前页码
- `size`: 每页大小
- `total`: 总记录数
- `pages`: 总页数
- `records`: 数据列表
- `hasNext`: 是否有下一页

### 2. Mapper 层添加手动分页方法

**位置**：`CommodityMapper.java`

```java
/**
 * 手动分页查询商品列表
 * 使用 LIMIT 实现分页
 */
@Select("SELECT * FROM commodity_info LIMIT #{offset}, #{limit}")
List<CommodityInfo> selectByPage(@Param("offset") Long offset, @Param("limit") Long limit);

/**
 * 查询商品总数
 */
@Select("SELECT COUNT(*) FROM commodity_info")
Long selectTotalCount();
```

**核心原理**：
- 使用 MySQL 的 `LIMIT offset, limit` 语法实现分页
- `offset` = (当前页 - 1) × 每页大小
- 例如：第1页 offset=0，第2页 offset=8，第3页 offset=16

### 3. Service 层实现分页逻辑

**位置**：`GoodServiceImpl.java`

```java
@Override
public PageResult<CommodityInfo> getGoodsByPage(Long current, Long size) {
    // 1. 计算偏移量
    Long offset = (current - 1) * size;
    
    // 2. 查询当前页数据
    List<CommodityInfo> records = commodityMapper.selectByPage(offset, size);
    
    // 3. 查询总记录数
    Long total = commodityMapper.selectTotalCount();
    
    // 4. 计算总页数（向上取整）
    Long pages = (total + size - 1) / size;
    
    // 5. 判断是否有下一页
    Boolean hasNext = current < pages;
    
    // 6. 封装返回结果
    return PageResult.<CommodityInfo>builder()
            .current(current)
            .size(size)
            .total(total)
            .pages(pages)
            .records(records)
            .hasNext(hasNext)
            .build();
}
```

**分页计算说明**：
- **偏移量计算**：`offset = (current - 1) * size`
  - 第1页：(1-1) × 8 = 0，查询第 0-7 条
  - 第2页：(2-1) × 8 = 8，查询第 8-15 条
  - 第3页：(3-1) × 8 = 16，查询第 16-23 条

- **总页数计算**：`pages = (total + size - 1) / size`
  - 例如：total=50, size=8
  - pages = (50 + 8 - 1) / 8 = 57 / 8 = 7（向下取整）

### 4. Controller 层添加分页接口

**接口路径**：`GET /api/goods/page`

**参数**：
- `current`: 当前页码（默认 1）
- `size`: 每页大小（默认 8）

**示例请求**：
```
GET http://localhost:8080/api/goods/page?current=1&size=8
```

**返回格式**：


## 前端实现

### 1. API 接口封装

位置：`vue-pet/src/api/goods.js`

新增方法：
- `getGoodsByPage(current, size)`: 分页获取商品列表
- `getGoodsByPageSafe(current, size)`: 安全版本，自动处理错误

### 2. 商品列表组件改造

位置：`vue-pet/src/components/shopping/list/List.vue`

**核心功能**：
1. 使用 Vant 的 `List` 组件实现下拉加载
2. 维护分页状态：
   - `goodsList`: 商品列表数组
   - `currentPage`: 当前页码
   - `loading`: 加载状态
   - `finished`: 是否加载完成

3. `onLoad` 方法：
   - 自动触发加载下一页数据
   - 追加数据到列表
   - 判断是否还有更多数据

**使用方式**：
- 页面初始化时自动加载第一页（8条数据）
- 用户向下滚动到底部时，自动加载下一页
- 显示"加载中..."和"没有更多了"提示

## 技术要点

### 后端
- **手动分页**：使用 SQL 的 `LIMIT offset, limit` 实现
- **两次查询**：
  1. 查询当前页数据：`SELECT * FROM ... LIMIT offset, limit`
  2. 查询总记录数：`SELECT COUNT(*) FROM ...`
- **按需查询**：只从数据库读取当前页的数据，提高性能
- **简单直接**：不依赖复杂的分页插件，代码清晰易懂

### 前端
- **Vant List 组件**：提供下拉加载功能
- **状态管理**：维护页码、加载状态、完成状态
- **数据追加**：新数据追加到现有列表，而不是替换
- **自动触发**：滚动到底部自动触发加载

## 优势

1. **无依赖问题**：不需要配置 MyBatis-Plus 分页插件
2. **简单明了**：分页逻辑清晰，易于理解和维护
3. **灵活可控**：可以轻松添加自定义查询条件
4. **性能优化**：只查询需要的数据，减少数据库压力

## SQL 执行示例

假设数据库有 50 条商品数据，每页 8 条：

**第1页请求**：`current=1, size=8`
```sql
-- 查询数据
SELECT * FROM commodity_info LIMIT 0, 8;
-- 查询总数
SELECT COUNT(*) FROM commodity_info;
```

**第2页请求**：`current=2, size=8`
```sql
-- 查询数据
SELECT * FROM commodity_info LIMIT 8, 8;
-- 查询总数
SELECT COUNT(*) FROM commodity_info;
```

**第7页请求**：`current=7, size=8`
```sql
-- 查询数据（只返回2条）
SELECT * FROM commodity_info LIMIT 48, 8;
-- 查询总数
SELECT COUNT(*) FROM commodity_info;
```

## 优化建议

1. **缓存总数**：如果数据不经常变化，可以缓存总记录数，避免每次都查询
2. **添加索引**：在常用的查询字段上添加索引，提高查询速度
3. **分类分页**：支持按分类进行分页查询
4. **搜索分页**：支持搜索结果的分页
5. **排序功能**：添加按价格、销量等排序功能
